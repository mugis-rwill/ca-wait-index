# CliniDashboard

This is a capacity/demand comparison tool for hip & knee replacement wait times across
Canadian provinces (2020–2025), built from real CIHI wait-time data and
StatCan population data. This repo has scripts that ingests raw data and calculates the capacity & demand metrics for each province and saves them as JSON files, then uses Javascript to render it.

## Architecture

```
raw_data/  →  scripts/ (ingest + panel) →  output/panel.json
                                           output/regional_panel.json
```

The page computes nothing: `panel.py` fits the model, bootstraps the intervals
and writes the JSON; `script.js` draws it. That split is unchanged — what
changed is what gets drawn.

## What each part does

- **`scripts/ingest_provincial.py`** — reads CIHI's "Wait Times for Priority
  Procedures" workbook into a flat frame, and holds the shared constants
  (`PROVINCES`, `PROCEDURES`, `METRIC_MAP`). Reading only; no reshaping and no
  statistics.
- **`scripts/panel.py`** — the provincial pipeline. Builds the 120-row
  province-year panel and fits the pooled model. See below.
- **`scripts/regional_panel.py`** — the same across ~546 region-years, using
  real health-region population denominators.
- **`scripts/crosswalk.py`** — reconciles CIHI health-region names with
  StatCan's (50 of 53 exact, 2 approximate, 1 refused).
- **`scripts/uncertainty.py`** — distribution-free confidence intervals for a
  reported median, from case volume plus the province's own P50 / P90 /
  %-benchmark.
- **`index.html`** — the site's front page, generated by
  `scripts/make_benchmark_doc.py`. Provincial hip/knee wait distributions drawn
  against the 182-day benchmark, with year, procedure, ordering and volume-strip
  controls. Data is embedded in the file, so it needs no `fetch()` and works
  from `file://` as well as over HTTP. **Do not hand-edit it** — edit
  `scripts/benchmark_template.html` and regenerate, or the next run overwrites
  the change. The same generator writes `output/benchmark_view.html`, the
  identical page minus the document skeleton, for publishing as an Artifact.

- **`script.js` / `panel.css`** — orphaned. They belong to the previous
  front page (the pooled-panel regression view) that `index.html` replaced, and
  nothing loads them now. `style.css` is still referenced by `trendlines.html`.

- **the previous front page** — rendered the province effects from the pooled
  panel model with their bootstrap intervals, the national year trend, a
  per-province detail view, and a model card. It is no longer served. Its
  markup is gone; `script.js` and `panel.css` are what remain of it, and
  `style.css` is untouched because `trendlines.html` still uses it.

Measures used throughout:

- **capacity** = surgical volume per 100k of the 65+ population
- **demand** = see "Which demand variable" below — `share65` between provinces,
  `share75` within one
- **pctBenchmark** = CIHI's "% meeting benchmark", carried through as a
  secondary signal rather than folded into an axis

### The panel model (`panel.py`, `regional_panel.py`)

The previous design (`compute.py`, `run_provincial.py`, both now removed) fit
one regression per procedure-year — 10 provinces against 3 parameters, leaving
7 residual degrees of freedom. That is not enough to
estimate a per-province claim or to check one. On 2025 hip it produced
R² = 0.018, a capacity coefficient with the wrong sign, Alberta carrying
leverage 0.869, and a PRESS R² of −0.39 (worse out-of-sample than predicting
the national median for everyone).

`panel.py` fits **one model over all 120 province-years** instead, and splits
the result into the three things the per-year design conflated:

| | meaning |
|---|---|
| **province effect** | how slow a province is *persistently* — the product |
| **year effect** | what the whole country did that year |
| **residual** | this province, this year, unusually good or bad |

The dependent variable is `log(wait)`, so coefficients read as percentage
effects and predictions can never come out negative — which removes the need
for the old `max(0.0, expected)` floor, a guard that silently turned a
least-squares residual into something else whenever it fired. Because the panel
is balanced,
every row carries identical leverage (`k/n` = 0.133), so no single province can
tilt the fit the way Alberta did.

`regional_panel.py` does the same across ~546 region-years, and reports which
CIHI regions have no population denominator rather than inventing one.

### Which demand variable

Three are computed, because they measure different things and are not
interchangeable. `capacity` is always volume per 100k of the **65+**
population; these are the numerator-side demand measures:

| Variable | Meaning | LOPO R² | Use for |
|---|---|---:|---|
| `share65` | 65+ as % of total population — how old the province is | **+0.117** | comparing provinces |
| `share75` | 75+ as % of 65+ — how old its seniors are | +0.056 | change within a province (b = +0.088, p = 0.007 under province FE) |
| `growth65` | YoY growth of 65+ — the original measure | −0.099 | refitting the old spec only |

`growth65` is the weakest of the three and is what gave Alberta leverage 0.869:
it reads 5.06% there against 2.69–3.55% everywhere else. It is also **−0.82**
correlated with `share65`, so a fast-growing senior population mostly marks a
province that is *young* overall — the opposite of demand pressure.

### Why the window starts at 2020

CIHI's workbook runs to 2008 and coverage is complete from 2010, so a 354-row
panel is available. Don't use it. `era_stability()` in `panel.py` runs the check:

- **It buys no precision.** Cluster-robust SEs are asymptotic in the number of
  *clusters* — 10 provinces, whether the panel holds 6 years or 18. Tripling
  the rows moved `se(share65)` from 0.0136 to 0.0166, slightly the wrong way.
- **The eras are different systems.** Rank correlation of province means between
  2010–2019 and 2020–2025 is **+0.10**; an F test for a break in the province
  effects gives **F = 23.2, p = 1.6e-29**. Nova Scotia ran 207 days pre-COVID
  (slowest in Canada) and 168 after (second fastest) — the only province to
  improve. Pooling averages two regimes and describes neither: on 2010–2025
  Nova Scotia's effect comes out at 1.326, "a slow province", which is the
  opposite of what has been true since 2020.

`--from-year` will override the default and prints a warning if set below 2020.
To buy real inferential precision, add *clusters*, not years: clustering the
regional panel by region gives 50 instead of 10 and cuts `se(log_volume)` from
0.099 to 0.059 (at the cost of assuming regions within a province are
independent, which they are not — a wild cluster bootstrap on province clusters
is the principled fix).

### Reporting period

CIHI's `Data year` is **April–September** unless suffixed `FY` (fiscal year) or
`Q3Q4` (October–March) — so a bare `2025` is a *half-year* count. The 2024 rows
confirm it: Apr–Sep plus Q3Q4 equals FY exactly (Ontario 11,515 + 11,757 =
23,272). The removed pipeline took the leading four digits of `Data year`,
collapsing all three periods into one integer, then let `aggfunc="first"` pick
whichever row pandas saw first — which landed on April–September by row-ordering
luck rather than by rule. When `2025FY` is published that would have silently
doubled Ontario's volume with no error raised. `panel.py` and
`regional_panel.py` match the period string exactly instead.

## Running the pipeline

```bash
pip install -r scripts/requirements.txt
cd scripts
python3 panel.py            # 120 province-years -> output/panel.json
python3 regional_panel.py   # ~546 region-years  -> output/regional_panel.json
```

Both default to the files in `raw_data/`; pass `--xlsx` / `--population` to
override, and `--from-year` on `panel.py` to widen the window (it warns below
2020 — see above). `panel.py` takes ~15s, most of it the 2,000-draw block
bootstrap behind the province-effect intervals.

## Viewing the site

The page fetches JSON with relative `fetch()`, so it needs to be served over
HTTP rather than opened as a `file://` URL:

```bash
python3 -m http.server 8000   # from the repo root
# then open http://localhost:8000/index.html
```

Run `panel.py` and `regional_panel.py` first — the page reports a clear error
if `output/panel.json` is missing rather than failing silently. The regional
drill-down is a progressive enhancement: the page is complete without
`regional_panel.json`.

## The descriptive track

`build_master_table.py`, `matched_pairs.py` and the three page generators are a
separate line of work from the panel model above, and share none of its code.
They read the CIHI workbook and the StatCan population file directly and fit
nothing. See `docs/` for the window-and-provenance findings and the limitations
page.

```bash
cd scripts
python3 build_master_table.py                    # 120 rows, Apr-Sep 2020-2025
python3 build_master_table.py --window fy        #  98 rows, fiscal 2020-2024
python3 matched_pairs.py                         # the matching rule, Apr-Sep
python3 matched_pairs.py --table ../output/master_table_fy.csv --tag _fy
python3 make_benchmark_doc.py                    # -> ../index.html
python3 make_pairs_doc.py ; python3 make_fy_pairs_doc.py
```

Every row of `output/master_table*.csv` carries a `cihi_source_rows` column with
the Table 1 row numbers behind it, so any published figure can be traced to the
workbook in a few seconds.
